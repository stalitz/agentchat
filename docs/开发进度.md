## 2026-09-16 · 复测：codex 的执行路径由「可用性」决定、与模型来源无关；两条路径的工具调用都能显示

- **触发（用户）**：*「之前修 codex 要在桌面端显示会话才改成 app-server，本地 gemma 走 codex exec，是不是就不会在桌面端显示？你是根据配置走不同的路径吗，不会串吧？工具调用在 app-server 也能显示吗，这两个你都测一下」*
- **澄清（读代码，无改动）**：路径**不是**按配置选的——`run()` 先试 app-server，**仅**在 `_CodexAppServerUnavailable`（进程起不来 / `initialize` 无响应 / `thread/start` 失败）时回退 `codex exec`；无任何开关可改，与 `model` / `base_url` 无关。`_codex_provider_overrides()` 是**两条命令共用**的同一个方法（exec 侧 `_codex_cmd`、app-server 侧 `_ensure_appserver` 各调一次），故不存在「配了本地 gemma 就被切到 exec」或两路配置串味。app-server 的 `thread/start` **不传沙箱策略**（沿用 codex 默认）。
- **真机复测（本地免费 gemma，`agent-probes/probe_codex_paths.py`）**：
  - 用例 A（默认分发 `run()`，agent 配 `base_url=http://localhost:11434`）：**未回退**（exec 调用计数 0）⇒ 仍走 app-server；事件含 `tool_use{exec_command}`，正文为 5 个 delta（真流式特征）；rollout `source="vscode"`（**桌面端可见**）。

## 2026-09-14 · 新增「中止 / 继续」——turn 级中断（与轮边界的暂停/停止/恢复互不干扰）

- **触发（用户提问 → 定案）**：用户问「暂停现在是做什么用的，继续讨论不是需要输入才能继续吗」，据此确认既有三个控制键（暂停 / 恢复 / 停止）**只在轮边界生效**——正在流式生成的那一轮一定会跑完，模型死循环时掐不断。用户定案：**"中止和继续应该和现在已有的几个都是不同的，应该做成一个单独的功能，互不干扰"**。
- **控制四层（本次补齐第 4 层）**：

  | 能力 | 生效时机 | 语义 | 模式 | 入口 |
  |---|---|---|---|---|
  | 暂停 / 恢复 | 轮边界 | 挂起后由用户解挂，不结束本场 | 辩论 | 底部控件行（原「继续」**改名「恢复」**，仅解挂） |
  | 停止 | 轮边界 | 当前发言跑完，不再开下一轮 | 辩论 | 底部控件行 |
  | **中止** | **当场（turn 级）** | 立刻掐断正在生成的输出，**本次发言作废** | 对话 + 辩论 | 主按钮槽位（生成中变红色「中止」） |
  | **继续** | 下次运行 | 由**被中止的那个 agent** 就当前议题重新完整发言 | 对话 + 辩论 | 主按钮槽位（有待续接记录时显示「继续（<agent> 重新发言）」） |

- **作废口径（用户确认）**：被中止的半截发言**仍然落盘并显示**（灰化 + 「已中止」角标，可追溯「中间出过错」），但**不计入轮次、不作为其他 agent 的上下文、不作为结论来源**；续接时由**同一个 agent、同一 round_i** 重说（不重置回第一个 agent，也不消耗半轮预算）。
- **中断通道（协议优先、硬停兜底）**，`AgentRuntime.interrupt()` 返回实际通道备查：
  - codex app-server → `turn/interrupt{threadId,turnId}` JSON-RPC。turn id 来自 `turn/start` 应答的 `result.turn.id` 或 `turn/started` 通知的 `params.turn.id`，`turn/completed` 时清空（防打到已结束的 turn）；每次 `turn/start` 前先 `_as_turn_id = None` 清残留。
  - claude-code → 往 stdin 写 `control_request{request:{subtype:"interrupt", cancel_queued:true}}`。
  - codex exec 兜底路径 / 协议帧写失败 → `_kill_proc_group` 整组硬停。
- **改动**：
  - `executor.py`：`AgentRuntime` 新增 `_live_proc`（在途 turn 子进程，turn 结束注销）与 `_as_turn_id`；`_stream_subprocess(..., keep_stdin=)` —— claude 走 stream-json 必须**保住 stdin 才能发中断帧**，随之而来两个必须处理的副作用：① `_user_frame` **补行尾 `\n`**（stream-json 输入是 NDJSON 按行解析，原先靠写完关 stdin 的 EOF 断行才没暴露，stdin 不关就会首轮卡死）；② stdin 不关则 claude 发完 `result` **不会自退** → 新增 `_is_claude_turn_end()` 识别 `result` 事件后主动关 stdin + wait，否则生成器永久阻塞（关 stdin 也顺带避免留会话锁，续接走 `--resume` 才干净）。新增 `interrupt()` / `hard_kill()`。

## 2026-09-14 · 修复 codex app-server 进程泄漏（整组回收 + 先 SIGTERM）+ 断流可诊断

- **③ 结论：失败的工具调用实时不显示，不是 app 过滤掉的**。app 侧 `_codex_native_tool_use` **不按 status 过滤**，探针也证明 `status=failed` 的 item 会实时产出 `tool_result(is_error=true)`。真正原因分两种：
