# 接口文档 · Agent CLI Orchestrator

基础地址：`http://127.0.0.1:8777`
所有 REST 响应为 JSON；配置类接口请求体为 JSON。

---

## 1. REST 接口

### 1.1 获取全部配置
`GET /api/config`
```json
{
  "projects": [ {ProjectConfig...} ],
  "teams":    [ {TeamConfig...} ],
  "agents":   [ {AgentConfig...} ]
}
```
> 注意：三项均为**数组**（非字典）。此外 `/api/config` 还返回 `settings`（全局设置）。

### 1.2 Agent
- `POST /api/agents` — 创建/更新。请求体 `AgentConfig`（缺 `id` 时服务端生成）。返回完整对象。
  ```json
  {"name":"架构师","type":"claude-code","role":"系统架构师"}
  ```
  > Agent 不再含 `timeout` / `max_rounds` 字段——前者是全局设置（见 §1.7），后者是发起讨论时的参数。
- `DELETE /api/agents/{aid}` — 删除。返回 `{"ok":true}`。

### 1.3 Team
- `POST /api/teams` — 创建/更新。
  ```json
  {"name":"双核Team","agent_ids":["ag_arch","ag_impl"]}
  ```
- `DELETE /api/teams/{tid}`.

### 1.4 Project
- `POST /api/projects` — 创建/更新。
  ```json
  {"name":"demo","path":"/tmp/demo-proj","team_ids":["tm_demo"]}
  ```
- `DELETE /api/projects/{pid}`.

### 1.5 会话（session）管理
每个项目下可有**多条会话**，每条会话独立保存历史与共识记忆。聊天区跟随当前选中的会话。

- `GET /api/sessions` — **全局**会话列表（跨项目扁平化），每条附带 `project_id` / `project_name` / `team_id` / `team_name`，按 `updated_at` 倒序。前端中栏默认按项目加载（见下条），此接口保留供跨项目聚合使用。
  ```json
  { "sessions": [ { "id":"s_xxx", "title":"会话名", "project_id":"pr_1", "project_name":"demo", "team_id":"tm_1", "team_name":"双核Team", "created_at":"...", "updated_at":"...", "message_count":2, "preview":"首条内容预览" } ] }
  ```
- `GET /api/sessions/{pid}` — 列出该项目的全部会话（按 `updated_at` 倒序）。
  ```json
  { "sessions": [ { "id":"s_xxx", "title":"会话名", "team_id":"tm_1", "created_at":"...", "updated_at":"...", "message_count":2, "preview":"首条内容预览" } ] }
  ```
- `POST /api/sessions/{pid}` — 新建会话。请求体可选 `{ "title": "会话名", "team_id": "tm_1" }`，省略 title 则默认「新会话」。返回 `{ "session": {id,title,team_id,...} }`。
- `GET /api/session/{pid}/{sid}` — 读取某会话完整内容。
  ```json
  { "id":"s_xxx", "title":"会话名", "team_id":"tm_1", "exists":true, "messages":[ {round,speaker,role,content,thinking,ts}... ], "agent_sessions":{ "A":"<cli_session_id>", "B":"<cli_session_id>" } }
  ```
  会话不存在时 `exists:false`、`messages:[]`。`agent_sessions` 为各 agent 的持续 CLI 会话 id 映射（见 FR9），用于点历史会话时 `--resume` 恢复对应 agent 会话。`messages[].ts` 为发言时间戳（本地时间 `YYYY-MM-DD HH:MM:SS`）：新消息落盘自动写入；历史消息由 `backend/backfill_timestamps.py` 从 claude transcript 回填（无对应 transcript 的失败空跑消息无 ts）。
- `DELETE /api/session/{pid}/{sid}` — 删除会话。返回 `{ "ok":true }`。
- `GET /api/session/{pid}/{sid}/prompts` — 返回该会话提示词日志（每轮发给 agent 的完整 prompt）。
- `GET /api/session/{pid}/{sid}/tools` — 返回该会话工具调用日志（end_discussion 每次调用：`{ts, agent, round_i, action(rejected/proposed/repeat/confirmed), reason, msg}`）。
- WS 动作（`start` / `stop` / `pause` / `resume` / `inject`）均带 `session_id`；**多会话可并行**——后端按 sid 路由，只锁目标会话自身，其他会话的讨论互不影响。

> 存储位置：`<项目>/.agentchat/sessions.json`（一个数组，每项为一条会话，含 `messages` / `agent_sessions` / `conclusion`）。

### 1.6 目录浏览（项目目录选择器）
`GET /api/fs?path=<目录>` — 返回该目录下的子目录列表（不含隐藏目录，不含文件）。`path` 省略时默认用户主目录（`$HOME`）。
```json
{ "path": "/Users/me/www", "parent": "/Users/me", "dirs": [ {"name":"agent-chat","path":"/Users/me/www/agent-chat"} ] }
```
> 浏览器原生 `<input webkitdirectory>` 出于安全不会暴露真实绝对路径，故前端用此接口做服务端驱动的目录树选择器，拿到真实绝对路径回填到项目目录。

### 1.7 首页
`GET /` — 返回 `frontend/index.html`。

## 2. 配置模型字段

**AgentConfig**
| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| id | str | 服务端生成 | 唯一标识 |
| name | str | — | 显示名（必填） |
| type | `"claude-code"\|"codex"\|"fake"` | — | agent 类型（必填） |
| role | str | "" | System Prompt / 系统提示（角色） |
| model | str? | null | 模型名（透传给 CLI） |
| cli_args | str | "" | 额外 CLI 参数（空格分隔） |
| fake_terminate_round | int | 0 | 仅 fake：第 N 轮（含）起末尾加 TERMINATE（规划中改发出 `end_discussion` 工具调用，见需求文档 FR5.3a）；0=永不 |

> **轮次上限 `max_rounds` 不在 Agent 上**——它是「一场讨论」的属性，由发起讨论时通过 WebSocket 的 `start` 消息传入（见 §3），所有 agent 共用同一个上限。
> **单轮超时 `timeout` 不在 Agent 上**——它是全局设置 `default_timeout`（见 §1.7 / AppSettings），对所有 agent 统一生效。
> **运行目录不在 Agent 上**——agent 跟随其所属项目的目录运行（会话以项目目录为 `cwd` 启动 CLI），故 AgentConfig 无 `cwd` 字段。

### 1.7 全局设置（AppSettings）
存于 `config.json` 顶层 `settings`，对所有讨论统一生效，改完即时生效无需重启。
- `GET /api/config` 返回的 `settings` 字段即当前值。
- `POST /api/settings` — 更新全局设置。请求体 `AppSettings`，返回更新后的 `settings`。
  ```json
  {"default_timeout": 300}
  ```
**AppSettings**
| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| default_timeout | int | 300 | 单轮静默超时（秒）：某 agent 连续该秒数不输出新内容即判卡死并终止该轮；流式输出过程不会触发 |
| ollama_num_ctx | int | 16384 | 发给 Ollama 的上下文长度（KV cache 上限）；仅内置网关生效，**不影响 Ollama GUI/全局设置**。实测 Ollama 的 OpenAI 兼容端点忽略 num_ctx、会把上下文拉满模型原生 128k（deepseek-r1:14b 单份吃 ~34GB）；内置网关改走原生 /api/chat 端点传 options.num_ctx，对辩论场景 16384 足够且把单份显存压到 ~12GB。改完即时生效无需重启 |

**TeamConfig**：`id`, `name`, `agent_ids: list[str]`。
**ProjectConfig**：`id`, `name`, `path: str`, `team_ids: list[str]`。

## 3. WebSocket 接口

`ws://127.0.0.1:8777/ws`

### 3.1 客户端 → 服务端（action 消息，JSON）
| action | 字段 | 说明 |
|--------|------|------|
| start | `project_id`, `team_id`, `session_id`, `task`, `max_rounds`(可选,默认12) | 启动会话；消息会写入 `session_id` 对应的会话（缺失时服务端自动新建）。`max_rounds` 为整场讨论轮次上限，语义为「每个 agent 发言次数」（N 轮 = 共 N×agent 数次发言）。Team 仅 1 个 agent 时后端强制 `max_rounds=1`（单 agent 模式，轮次不生效，仅一次完整回答） |
| stop | — | 立即终止 |
| pause | — | 暂停 |
| resume | — | 继续 |
| inject | `text` | 注入人工消息 |
| config / reload | `op:"reload"` | 服务端回传当前 config |

### 3.2 服务端 → 客户端（事件，JSON）
| type | 字段 | 说明 |
|------|------|------|
| system | `msg` | 系统提示（会话开始/暂停/继续/收敛/结束） |
| turn_start | `agent`, `role`, `atype` | 某 agent 开始本轮 |
| token | `agent`, `text` | 流式文本片段 |
| turn_end | `agent` | 本轮结束 |
| human | `text` | 人工介入消息 |
| error | `agent?`, `text` | 错误（CLI 失败/超时/缺配置） |

### 3.3 示例（调试 Team 仅 Fake，任务「设计登录」）
```json
{"type":"system","msg":"会话开始 · agent 数=1 · 上限 6 轮"}
{"type":"turn_start","agent":"假Agent（调试）","role":"...","atype":"fake"}
{"type":"token","agent":"假Agent（调试）","text":"[FAKE:假Agent（调试）] 我是「...」..."}
{"type":"turn_end","agent":"假Agent（调试）"}
{"type":"system","msg":"假Agent（调试） 标记 TERMINATE，会话收敛"}
{"type":"system","msg":"会话结束"}
```
