# 使用说明 · Agent CLI Orchestrator

## 1. 启动服务

```bash
cd /Users/stalitz/www/agent-chat
.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8777
```

浏览器打开 **http://127.0.0.1:8777**

> ⚠️ 不要用 WorkBuddy 的 `static-html` 预览链接打开 `index.html`——那只是单独加载 HTML，
> 连不到后端，下拉框会是空的、按钮全无反应。必须用上面的真实地址。

## 1.1 左侧项目树：导航 / 新建 / 行内编辑

左侧按顺序展示 **项目 → Team → Agent**，每个节点都带类型徽章（项目 / Team / Agent），一眼能分清层级：

- **导航（点名称）**：点击节点**名称**=进入对应上下文——点**项目名** → 中栏加载该项目的会话；点 **Team / Agent 名** → 右侧输入区预选该 Team / 单 agent。浏览与编辑解耦。
- **新建**：左栏底部「+ 项目」「+ Team」「+ Agent」按钮，弹出空白表单。
- **编辑**：点击节点行内 **✎ 图标**（不是点名称），弹出**已预填当前内容**的编辑表单，改完点「保存」。
- **删除**：编辑表单里点「删除」按钮（带二次确认）即可移除；删除 Project / Team 仅移除该资源本身，不影响被引用的 Agent。
- **全局设置**：左栏底部「⚙ 设置」按钮 → 弹窗改 **单轮静默超时**（`default_timeout`，默认 300s），保存即全局生效、无需重启。左栏折叠成图标栏后，底部同样有 ⚙ 入口。

> 所有改动实时写入 `data/config.json` 并立即刷新左侧树，无需重启服务。

## 2. 首次使用（推荐先试 Fake agent，零成本）

当前 `data/config.json` 已内置一套可直接用的数据：

- 项目 `demo` → 目录 `/tmp/demo-proj`
- Team `双核Team（Claude+Codex）`：架构师(Claude) + 实现者(Codex)
- Team `调试Team（仅 Fake）`：只含一个 **假Agent（调试）**
- Agent `假Agent（调试）`：类型 `fake`，`fake_terminate_round=3`（第 3 轮触发收敛）

**调试步骤**：
1. 在**左栏点项目名 `demo`** —— 中栏会加载它的会话列表。
2. 在**右侧输入区「Team」下拉**选 Team（中栏若无会话，点「＋ 新」开一条）。
3. 选 `双核Team` → 输入区是**辩论模式**：填任务点「开始讨论」，看回合交替、TERMINATE 收敛。
   选 `调试Team（仅 Fake）` → 输入区是**对话模式**：直接输入消息按 Enter 发送，一问一答，可以一直聊。
4. 全程**不调用任何 CLI、不烧 token**。

## 3. 用真实 agent 跑

1. 左侧「+ Agent」新建：类型选 `claude-code` 或 `codex`，填角色 prompt（如「系统架构师」）。
   （注意：讨论轮次 `max_rounds` 与单轮超时 `timeout` 都不在这里设——前者是发起讨论时填，后者是全局设置，见第 2 步。）
2. 单轮静默超时 `default_timeout`（默认 300s）为 App 全局设置：点左栏底部「⚙ 设置」改，保存即生效，无需重启（也可直接编辑 `data/config.json` 顶层 `settings`）。
3. 「+ Team」把若干 agent 编成组；「+ 项目」建项目并关联 Team。项目目录**不用手敲**：点「选择文件夹」会弹出目录树（服务端驱动，可拿到真实绝对路径），一层层进入后点「选择此目录」即回填。
4. 左栏点项目名选中、右侧输入区选 Team。输入区会显示当前模式标识，并按模式变形：
   - **Team 含 ≥2 个 agent → 辩论模式**：填任务点「开始讨论」，「最大轮次」可填本场上限（默认 12），agent 轮流发言，可暂停/继续/停止/人工介入。
   - **Team 仅 1 个 agent → 对话模式**：退回普通人机对话。输入框直接打字，**Enter 发送、Shift+Enter 换行**（也可点「发送」），一问一答，可以一直聊下去。轮次、暂停/继续/停止、人工介入这些辩论专用控件会自动隐藏——它们在对话模式下不适用。

> 真实 agent 需要本机 `claude` / `codex` 已登录并接入目标模型（如 DeepSeek）。
> Claude Code 接 DeepSeek 需前置 Anthropic→OpenAI 翻译代理（见开发文档 §4/需求文档 §6）。

### 3.1 思考模型（如本地 Gemma）的思考过程展示
- 若某 agent 走内置网关接入了**思考模型**（如 Ollama 的 gemma4:26b，会先输出推理链再给答案），对话里除了答案，还会多出一个**可折叠的 `💭 {agent 名} 的思考过程` 气泡**（按 agent 类型着色：Claude 蓝 / Codex 绿 / Fake 橙，一眼分清是谁在思考）——点开即看模型一步步怎么想的。思考过程会随答案一起**落盘进对话历史**（刷新后仍在、渲染为可折叠块），但**不回灌 prompt 上下文**，不会污染多轮讨论。
- 答案按**逐字（打字机）**效果吐出，不会整段一次性蹦出来。思考模型若没产出推理（例如太简单的问句），则只显示答案、不出现思考气泡。
- 接入方式：编辑该 claude-code agent 表单，「模型来源」选「本地 Ollama · gemma」，确认 `model` 填的是你本机 `ollama pull` 的真实 tag（如 `gemma4:26b`），保存即可。前置条件：本机 Ollama 已运行且已 `ollama pull` 对应模型。
- **开/关思考（三级开关，优先级 会话 > agent > 全局）**：① **全局**——⚙ 设置 →「思考（全局）」，作用于**全部 agent**；② **某个 agent**——编辑 agent 表单 →「思考（本 agent）」，三态：继承全局 / 开 / 关（要单独限制某个 agent 就在这里设）；③ **单场会话**——会话头部「💡 思考」，优先级最高。关闭后能显著降低输出量/耗时。
  - **生效范围（按后端）**：**Ollama（经内置网关）完全生效**（网关带 `think:false`，模型不再产思考）；**codex** 生效（降 `model_reasoning_effort`，属尽力而为，取决于所连模型是否支持）；**真实 claude 直连不生效**——Claude Code CLI 未提供 `--think` 类开关，其思考由模型本身决定（已知限制）。

## 4. 控制条说明

| 按钮 | 模式 | 作用 |
|------|------|------|
| 发送 | 仅对话模式 | 发一条消息给这个 agent，它回一条；可无限续。Enter 等同点它 |
| **中止** | **两种模式都可用** | **当场掐断模型正在生成的输出**（turn 级中断）。模型死循环、跑到一半发现方向不对时用它。本次发言**作废**：气泡保留但灰化 + 标「已中止」，不计入轮次、不会喂给其他 agent |
| **继续**（被中止后） | **两种模式都可用** | 让**被中止的那个 agent 就当前议题重新完整发言**（不是第一个 agent、也不需要你输入议题）。不消耗轮次，轮次接着算 |
| 开始讨论 / 继续讨论（已有 N 条） | 仅辩论模式 | 用所选 项目+Team+任务 启动编排循环；会话已有记录时点它往该会话续写（刷新后再点即“恢复讨论”）。**输入框为空时按钮禁用**——空议题不会让 agent 空跑；达成一致后想续必须输入新议题 |
| 停止 | 仅辩论模式 | 当前发言**跑完**后不再开下一轮（轮边界生效；想当场掐断用「中止」） |
| 暂停 / 恢复 | 仅辩论模式 | 在回合边界挂起 / 恢复（当前这一轮会跑完，之后不再开新轮）；「恢复」只是解除暂停，不需要输入内容 |
| 人工介入 | 仅辩论模式 | 讨论**进行中**发一条消息，作为下一轮的特殊输入插入，agent 基于它**继续**（不是停止）。Enter 等同点「介入」 |
| 记忆 | 两种模式 | 重新拉取并渲染当前选中的会话（含记忆摘要） |

> **主按钮是「三态复用」的**：空闲时=发送/开始讨论/继续讨论、模型生成中=**中止**、有未兑现的中止=**继续**（按钮上会写明由哪个 agent 重新发言）。因此生成中按钮**不再置灰**——否则模型死循环时没有任何可点的东西。

> **「中止」与「暂停 / 停止」不是一回事**（这是两套互不干扰的能力）：暂停/停止只在**轮边界**生效，当前这次发言必须跑完才停；**中止**是 turn 级的，点下去当场掐断输出。对应地，「恢复」（解除暂停）与「继续」（重说被中止的发言）也是两个不同按钮。

> 停止/暂停/恢复/介入只在**有讨论正在跑**时有意义。没有运行中的会话、或当前是对话模式时点它们，会在聊天区收到一条明确的错误提示说明为什么无效（不会再「点了没反应」）。中止/继续不受此限制：对话模式同样可用。
>
> **多会话可并行**：不同会话的讨论互不锁——A 会话在跑时，可以切到 B 会话正常发起/继续另一场讨论（只有同一会话重复发起才会被拒）；「讨论中」状态只作用于正在跑的那个会话，其他会话按钮照常可用。

### 3.1 三栏布局（项目左栏 + 会话中栏 + 聊天右栏）

界面为**三栏**：左侧**项目树（导航主干）**、中间**会话列表**、右侧**聊天区 + 输入区**。项目/Team/Agent 始终在左侧常驻、直观可见，不收进任何抽屉。

1. **左侧项目树**：默认展开，一眼看到项目 → Team → Agent 三级。点击节点**名称**=选中/导航（点项目名→中栏加载该项目的会话；点 Team/Agent 名→在右侧输入区预选该 Team/单 agent）；点击行内 **✎ 图标**=编辑（弹表单，新建/改名/改成员/删）。浏览与编辑解耦。
2. **项目栏可折叠**：点左栏顶部「–」收成**图标栏**（类似 IDEA 项目工具窗），只留每个项目的首字图标，点图标重新展开并选中该项目。
3. **中栏会话列表**：显示**当前选中项目**下的所有会话，每张卡片带 Team 徽章 + 首句预览，右上「删除」可移除（二次确认）；中栏头部「–」也可折叠隐藏，聊天区随之扩满。**折叠后左缘出现「≫ 会话」图标条，点它可重新展开会话栏**（避免隐藏后找不回）。
4. **同项目多会话**：点中栏「＋ 新」→ 弹窗选 **Team（+ 可选标题）**（项目取当前选中项）→ 创建并自动选中；之后右侧输入任务点「开始讨论」（辩论模式）/ 输入消息按 Enter（对话模式）即可。
5. **布局可拖拽调整**：项目栏与会话栏之间、会话栏与右栏之间各有**竖向分隔条**（鼠标移到边界变 `col-resize` 可左右拖），调整两栏宽度；右栏**聊天区与输入区之间有横向分隔条**（`row-resize`）可上下拖，调大/调小输入区与聊天区。三处尺寸记到浏览器 `localStorage`，刷新后保留。输入框本身也可拖右下角竖向放大。
6. **开新议题（达成一致 / 想换话题）**：在中栏点「＋ 新」**新建一条会话**再开最干净——新会话历史与记忆为空、首轮议题判定会重新生效；**不要在同一条已结束的会话上点「继续讨论」开新话题**，否则上一场的 TERMINATE / 结论会作为上下文混进来，且历史与记忆叠加串场。

- 发起讨论时，项目取自**当前选中的项目**，Team 取输入区的 Team 下拉（单 agent Team 时轮次自动置灰，进入对话模式），消息挂到**当前选中的会话**。
- **运行结束后刷新**分两种语义：
  - **辩论模式**跑完（上限 / 收敛 / 停止）后，中栏刷新该会话条数与预览，**聊天区重载**为持久化后的权威内容。
  - **对话模式**每条消息即时落库并回显，结束（收到 `run_end`，不播「会话结束」）后**仅刷新中栏计数与预览、不重载聊天区**，你正在看的内容不跳。

### 3.2 会话记录与恢复（刷新不丢）

- 每一轮的发言都会**实时落盘**到项目目录下的 `<项目>/.agentchat/sessions.json`（按会话分别保存 `messages` 与 `agent_sessions`，见接口文档 §1.5）。
- **页面加载时，左侧自动选中第一个项目并加载其会话、选中最新一条**，聊天区渲染其记录（顶部有「已恢复会话记录（N 条）」分隔条），所以刷新不会丢失。
- **恢复/继续**：**辩论模式**点「继续讨论」即可——新消息会追加到该会话，各 agent 在其**持续 CLI 会话**里天然看到此前所有轮次与历次结论，继续往下讨论（编排器只发「对手上一句 + 新议题」的 delta，不重搬历史）。`round_i` 从 0 重新计，所以下一发言者回到 Team 中第一个 agent（上下文连续，发言顺序从头轮替）。**对话模式**无需「继续」——每条消息即时发、即时回、可无限续。
- **agent 持久会话展示**：打开任一会话（从会话列表点开即自动恢复）时，聊天区会列出本会话下每个 agent 的持续 CLI 会话 id（如 `A → a1b2c3d4…`），证明 app↔agent 1:1 持续会话已生效；开新会话会生成新 id，历史会话则恢复旧 id。

## 5. 终止条件（三种并存 + 首轮议题判定）

1. **上限自动停**：跑满发起讨论时填的 `max_rounds`（整场讨论统一上限，与单个 agent 无关）。**这里的「轮」= 每个 agent 发言次数**——设 3 轮即每个 agent 各说 3 次（a,b,a,b,a,b），不是总共 3 次发言。
2. **手动停止**：点「停止」（轮边界生效：当前发言跑完不再开下一轮）。
3. **中止（turn 级，两种模式都可用）**：模型死循环 / 方向跑偏时点「中止」，**当场掐断**正在生成的输出。被中止的这次发言作废（气泡灰化 + 标「已中止」，不计轮次、不喂其他 agent）；点「继续」由该 agent 就当前议题**重新发言**，轮次接着算（不消耗半轮）。
4. **自发收敛（当前实现 = end_discussion 工具调用）**：agent 通过调用 `end_discussion(reason)` 结构化工具表达终止（见需求文档 FR5.3a），比纯字符串可靠——gate 结构性、不达标返回失败、agent 自行放弃。`TERMINATE` 关键词检测保留为兜底。
5. **共识终止（两阶段确认 + 最小轮数保护）**：辩论模式下，agent **真正接受上一位 agent 的结论并凝练总结**后，调用 `end_discussion(reason)` 工具提议终止。为防「第二个 agent 一轮就草草终止」：**至少完成两轮完整往返（每个 agent 都发过两次言）后**才允许调用（此前调用会收到「终止被拒」的失败结果，agent 自行放弃）；且**单方提议不算结束**——须另一方也调用 `end_discussion` 确认才真正收敛（显示「双方通过 end_discussion 达成一致，会话收敛」）。确认无时间窗：之后任意一轮对方再调即算确认。设几轮就至少跑满几轮，除非多轮后真达成共识才提前停。
6. **执行失败自动中止**：某 agent 调用出错（API 错误 / 空响应 / 会话恢复异常，如 claude 输出的 `API Error: ...`、`No response requested.`）时，该轮**不会把错误文本当发言**——聊天区广播错误 + 系统提示「X 执行出错，会话中止：…」，整场直接结束。报错信息不会被当成议题喂给其他 agent 继续讨论。

> **终止原因 / 会话结束会常驻聊天区、刷新不丢**：这些结论性系统消息已落库为 `speaker="system"` 条目，辩论模式 `run_end` 重载或手动刷新页面后仍可见；过程性提示（会话开始 / 暂停 / 继续）仅实时显示、不落库。

## 6. 记忆与产物

每个项目目录下的 `.agentchat/`：
- `sessions.json`：全部会话，每条含 `messages`（round / speaker / role / content）、`agent_sessions`（各 agent 持续 CLI 会话 id 映射）、`conclusion`（最近一次收敛结论，仅展示）。**记忆的"真相源"是各 agent 自己的 CLI 会话**——本地不另存滚动摘要，避免重复搬运浪费 token。
- `prompts/<会话id>.jsonl`：提示词日志，每行一条 `{round, agent, role, first_turn, ts, prompt}`——记录每轮发给 agent 的完整 prompt（即那条 delta，可见"到底喂了什么"）。
- 会话结束不丢、可续；前端「记忆」按钮可重新查看当前会话内容。
- **讨论调性（风格）**：发起讨论前，输入区下方「讨论风格」下拉可选 16 种风格（批判/温和/激进/唱反调/严谨/务实/幽默…或留空自由发挥）——选定后整场讨论每个 agent 都按该风格发言（每轮 prompt 注入「本场讨论风格」），并随会话保存、续接不变。想换风格就开新会话重选。注：**唱反调 / 批判 / 尖锐 / 激进 / 怀疑** 这 5 种「针对对方」的风格**从每个 agent 的第 2 次发言起生效**——首轮全体都先陈述己方立场（否则第一个发言者没有对手可反驳，只能拆自己的台，讨论方向会被带偏；中止后点「继续」属于接着已有交锋重说该轮，仍按该风格，不再当首轮）；其余 11 种风格（温和/中立/严谨/简洁/学术…）首轮照常生效。
- **会话标题修改**：中栏会话卡片的标题**双击**即进入行内编辑（输入框预填当前标题，最长 60 字），回车或失焦保存、Esc 取消；改名即时落盘并刷新列表，当前正在查看的会话头部标题同步更新。
- **提示词日志查看**：右栏头部「记忆」按钮旁有「提示词」按钮，点开弹窗列出该会话每轮发给 agent 的完整 prompt（首轮 `first_turn` 标记为 True，每轮均含「共识终止」指令），方便排查 prompt 构造是否正确。
- **工具调用日志查看**：「提示词」旁有「工具」按钮，列出该会话每次 `end_discussion` 工具调用（被拒·未达最小轮数 / 提议终止 / 重复提议 / 对方确认·终止，含轮次、调用者、reason 与说明）——一眼看出模型有没有尝试终止、为什么没成。

## 7. 常见问题

**Q：打开页面下拉框空、点啥都没反应？**
A：多半是用 WorkBuddy 静态预览打开了 HTML。改用 `http://127.0.0.1:8777` 真实地址。
若用真实地址仍无反应，看右上角状态栏——已加 `window.onerror`，JS 报错会直接显示在那里。

**Q：服务连不上（连接被拒）？**
A：uvicorn 进程可能已被回收。重新执行第 1 节启动命令即可。

**Q：想不烧 token 调试 UI / 编排？**
A：用内置 `调试Team（仅 Fake）`，或自建一个 `type=fake` 的 agent。

**Q：想换用别的 mock 配置？**
A：把 `tests/fixtures/mock-config.json` 复制到 `data/config.json` 即可。

**Q：codex agent 报 `Missing optional dependency @openai/codex-darwin-arm64`？**
A：codex CLI 的**平台原生包**跟跑它的 node 架构不匹配。`codex` 是个 JS 外壳（`#!/usr/bin/env node`），它按**执行它的那个 node 的 `process.arch`** 去找对应平台包：

- x64 node 找 `@openai/codex-darwin-x64`；arm64 node 找 `@openai/codex-darwin-arm64`。

本机（Apple Silicon）实测踩过两种组合：

- 用 Intel node（`/usr/local/bin/node`，x64）装的 codex → 只有 x64 包；若某进程（如从 WorkBuddy 启动的后端）PATH 里 arm64 node 在前 → 去找 arm64 包 → 崩。
- 修法（增量补上缺的那份，**不动**已装的那份）：

  ```bash
  # 用 arm64 npm 补装 arm64 平台包（版本号要带平台后缀，且与外壳版本对齐）
  <arm64-node>/bin/npm install -g '@openai/codex-darwin-arm64@npm:@openai/codex@<版本>-darwin-arm64' --prefix /usr/local
  ```

  注意：**不能**直接 `npm i -g @openai/codex-darwin-arm64`——平台包在 registry 上不是独立包名，而是 `@openai/codex` 的别名（`npm:@openai/codex@<版本>-<平台>`）。外壳版本用 `codex --version` 查；两份都装上后，x64 / arm64 node 都能跑。

**Q：codex agent 报 `Not inside a trusted directory and --skip-git-repo-check was not specified.`？**
A：codex 默认拒绝在「非 git 仓库、且不在 `~/.codex/config.toml` 受信项目列表（`[projects."..."] trust_level = "trusted"`）」的目录运行。app 已默认带上 `--skip-git-repo-check`（对齐 claude 侧 `--dangerously-skip-permissions`），若仍报此错说明跑的是旧代码，重启后端即可。

**Q：codex agent 能对话但无法执行 shell 命令（`sandbox-exec: sandbox_apply: Operation not permitted`，退出码 71）？**
A：这是 codex 自身沙箱在当前进程环境下无法应用策略（**嵌套沙箱**受限——若后端是从 WorkBuddy 之类自带沙箱的环境里拉起的，`sandbox-exec` 无法再套一层；换原生 arm64 二进制也无效，与架构无关）。纯文本任务与 `end_discussion` 工具**不受影响**（MCP 子进程不经该沙箱）。需要 shell 工具能力时：① 在**你自己的终端**前台启动后端（脱离外层沙箱），或 ② 给 agent 配 `cli_args = "-s danger-full-access"` / `--dangerously-bypass-approvals-and-sandbox`（放大权限，自行评估）。

**Q：codex agent 的 `end_discussion` 工具已自动接好了吗？**
A：已接好，无需手动配置——每次调用 codex 时会用 `-c` 注入 `terminate-signal` MCP 服务（复用 claude 侧同一个 `backend/terminate_signal_mcp.py`）+ 设 `default_tools_approval_mode="approve"`，**不动你的 `~/.codex/config.toml`**。若 codex 能对话但从不投终止票，先确认跑的是最新代码（重启后端）。
